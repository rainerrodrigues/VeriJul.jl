API

Loading designs

VeriJul.Device.load_dut — Function
load_dut(sources, top_module; kwargs...) -> DUT

Builds the design (or reuses a cached build) and loads it. Takes the same keywords as build_dut: build_dir, include_dirs, defines, parameters, verilator_args, internals, trace, force, verbose. With internals=true, internal signals can be read and written too (see signal).

dut = load_dut("filter.v", "filter")
dut.in_data = 0xFF

By default the build goes into VeriJul's build cache, one folder per design and set of options, so nothing is written to the current directory.

source
VeriJul.Device.DUT — Type
DUT

A loaded hardware design. Read and write its ports as properties:

dut.in_data = 0x42      # set an input (truncated to the port width)
dut.out_data            # read an output (or an input)

Ports up to 64 bits read back as UInt8/UInt16/UInt32/UInt64; wider ports read back as BigInt and accept any Integer.

Create one with load_dut, or with DUT(lib_path, top_module) for a library built with build_dut. List its ports with ports.

Port reads are type-stable: in f(dut) = dut.count, the compiler knows the result type from the port's width.

source
VeriJul.Device.ports — Function
ports(dut) -> Vector{HardwarePort}

The design's top-level ports, in declaration order.

source
VeriJul.Interop.settle! — Function
settle!(model)

Evaluates the model without writing a waveform sample, so combinational outputs reflect inputs you just set. Useful for designs without a clock.

source
VeriJul.Interop.enable_trace! — Function
enable_trace!(model, filename)

Starts writing a waveform to filename: a VCD file, or an FST file if the design was built with trace=:fst (see build_dut). The file is flushed and closed by destroy!.

VeriJul.Interop.destroy! — Function
destroy!(model)

Frees the C++ model, closes its VCD file and unloads the library. Safe to call more than once. Stop any running clock with stop_clock! first.

Simulation

VeriJul.SimCore.Simulator — Type
Simulator(dut; clock=:clk, half_period=5, stop_on_error=true)

Simulation state for a DUT (or a bare VerilatedModel): the current time and the clocks that drive it.

clock names the main clock input; tick and @tick wait on it unless told otherwise. Add more clocks with add_clock!.

sim.time is the simulation time of the most recent clock edge, and sim.cycle counts the rising edges of the main clock so far.

The clocks run in lockstep with the testbench: simulated time only advances while testbench code is waiting in tick, so printing, sleeping or any other I/O between ticks never skips an edge. Run concurrent testbenches with @testbench so the clock waits for all of them.

If a @testbench task throws, the clock stops and every task waiting on it gets that TestbenchError, so the failure reaches the caller instead of leaving tasks hanging. Pass stop_on_error=false to keep the clock running instead.

source
VeriJul.SimCore.add_clock! — Function
add_clock!(sim, name; half_period=5, phase=0)

Adds another 1-bit clock input. It toggles every half_period time units. All clocks run on the same timeline, so their edges interleave correctly. Wait for its edges with tick(sim; clock=name).

phase is measured from the current simulation time: before the simulation has started, the first toggle is at time phase; if clocks are added to a stopped simulation, the first toggle is phase after sim.time (or one half_period after it when phase is 0), so time never goes backwards. The simulator must not be running.

source
VeriJul.SimCore.start_clock! — Function
start_clock!(sim[, half_period]) -> Task

Starts the clocks in a background task. Whenever the testbench is waiting in tick, it toggles the clocks due at the earliest time, evaluates the design (writing a waveform sample if tracing is on) and wakes the waiting tasks. Simulated time does not advance while the testbench is busy, so no edge is ever skipped.

Passing half_period changes the main clock's half period. Throws if the clock is already running.

source
VeriJul.SimCore.stop_clock! — Function
stop_clock!(sim)

Stops the clocks and waits for the background task to finish. Tasks still waiting in tick get a ClockStopped error instead of hanging. Call this before destroy!-ing the design.

source
VeriJul.SimCore.tick — Function
tick(sim, n=1; clock=nothing, edge=:rising, timeout=nothing)

Waits for n edges of a clock (the main clock unless clock is given). edge is :rising or :falling. timeout is a wall-clock limit in seconds; when it passes, a TickTimeout is thrown.

Simulated time only advances while testbench code is waiting here, so whatever the task does between ticks (printing, sleeping, I/O) never makes it miss an edge.

Throws ClockStopped if the clock isn't running. @tick is shorthand for this.

source
VeriJul.DSL.@tick — Macro
@tick sim
@tick sim n
@tick sim n clock=:clk_b edge=:falling timeout=1.0

Waits for the next rising edge of the main clock, or n edges. Keywords are passed to tick: clock, edge and timeout (wall-clock seconds).

source
VeriJul.SimCore.reset! — Function
reset!(sim, port=:rst; cycles=2, active_high=true)

Asserts a reset input for cycles rising edges of the main clock, then releases it. The clock must be running. Use active_high=false for an active-low reset such as rst_n.

source
VeriJul.SimCore.run! — Function
run!(sim, n; clock=nothing) do cycle ... end
run!(sim, n)

Runs n cycles of the main clock (or clock) directly in the calling task, calling f(cycle) after each rising edge with cycle counting from 1. No background task and no task switches are involved, so this is the fastest way to run simple stimulus loops:

run!(sim, 1000) do cycle
    dut.in_data = rand(UInt8)
end

The clock must not be running (no start_clock!), since run! drives the clocks itself; tick and @testbench tasks don't work inside it. Use tick and @testbench when you need several things to happen concurrently. All clocks keep running on the same timeline, and hooks such as a WaveRecorder see every edge.

Waiting and testing

VeriJul.SimCore.wait_until — Function
wait_until(cond, sim; max_cycles=nothing, clock=nothing, edge=:rising, timeout=nothing) -> Int

Waits until cond() returns true, checking it now and then after every rising edge of the main clock (or the edge of clock). Returns the number of edges waited, so 0 means the condition already held.

max_cycles limits how many edges to wait: when it runs out, a WaitTimeout with the simulation time is thrown. timeout is a wall-clock limit in seconds, as for tick.

wait_until(sim; max_cycles=100) do
    dut.valid == 1
end

@wait_until is shorthand that also puts the condition's source text in the error message.

source
VeriJul.DSL.@wait_until — Macro
@wait_until sim condition
@wait_until sim condition max_cycles=100 clock=:clk_b edge=:falling timeout=1.0

Waits until condition (any Julia expression) is true, checking it now and after every rising edge of the main clock. Returns the number of edges waited. Keywords are passed to wait_until; when max_cycles runs out, the WaitTimeout message quotes the condition.

@wait_until sim dut.valid == 1 max_cycles=100
source
VeriJul.SimCore.wait_edge — Function
wait_edge(sim, port; edge=:rising, max_cycles=nothing, clock=nothing, timeout=nothing)

Waits for a port of the design to change, and returns its new value. edge is :rising (0 → 1) or :falling (1 → 0) for 1-bit ports, or :change for any change of a port of any width.

The port is sampled after every evaluation of the design, that is after each edge of any clock, since that is when outputs change. Inputs set by another testbench are seen at the next evaluation.

max_cycles counts rising edges of the main clock (or of clock); when it runs out a WaitTimeout is thrown. timeout is a wall-clock limit in seconds. Needs a simulator built from a DUT.

wait_edge(sim, :done)                     # wait for `done` to go high
wait_edge(sim, :state; edge=:change)      # wait for the FSM to move
source
VeriJul.DSL.@testbench — Macro
@testbench func

Defines func as usual and also a launch_<func>(sim::Simulator, args...; kwargs...) that runs func(sim, args...; kwargs...) as an asynchronous task, so it can wait on clock edges with @tick.

The clock waits for every launched testbench: no edge happens while any of them is busy between two ticks, so a driver and a monitor running together both see every edge. A finished testbench no longer holds the clock back.

@test inside a testbench records into the @testset that was active when it was launched, and failures show the simulation time and cycle. If the function throws, the task fails with a TestbenchError saying when; wait on the task inside a @testset to report it.

@testbench function drive(sim)
    sim.dut.in_data = 0xFF
    @tick sim
end

task = launch_drive(sim)
wait(task)
source
VeriJul.SimCore.launch — Function
launch(f, sim, args...; kwargs...) -> Task

Runs f(sim, args...; kwargs...) as a testbench task that the clock waits for: no edge happens while it is busy between two ticks. @testbench launchers use this.

The task records @test results into the @testset that was active when it was launched, adding the simulation time and cycle to every failure. If f throws, the task fails with a TestbenchError saying when, and (unless the simulator was created with stop_on_error=false) the clock stops: every task waiting on it gets that same error, so nothing is left hanging and the failure reaches whoever is waiting.

source
VeriJul.SimCore.WaitTimeout — Type
WaitTimeout

Thrown by wait_until, @wait_until and wait_edge when what they wait for doesn't happen within max_cycles clock cycles. Fields: what (a description), cycles (the limit), time and cycle (the simulation time and cycle count when it gave up).

source
VeriJul.SimCore.TestbenchError — Type
TestbenchError

The error a @testbench task fails with when its function throws. It says which testbench failed and when. Fields: testbench (the function name), time and cycle (the simulation time and cycle count), error (the original exception) and backtrace.

wait(task) and fetch(task) throw a TaskFailedException wrapping it, which a surrounding @testset reports as an error.

source
VeriJul.SimCore.ClockStopped — Type
ClockStopped()

Thrown by tick when the clock isn't running, or stops while a task is waiting for an edge.

source
VeriJul.SimCore.TickTimeout — Type
TickTimeout(seconds)

Thrown by tick when the requested edges don't arrive within timeout seconds of wall-clock time.

Verification components

VeriJul.Components.StreamBus — Type
StreamBus(; data, valid, ready=nothing, clock=nothing)

Names the ports of one valid/ready (AXI-Stream style) interface: a word moves on a rising clock edge when valid and ready are both high. ready=nothing means the interface has no backpressure (always ready). clock is the clock the interface belongs to (the main clock by default).

inp = StreamBus(data=:s_data, valid=:s_valid, ready=:s_ready)
out = StreamBus(data=:m_data, valid=:m_valid, ready=:m_ready)

Use it with send!, receive! and StreamMonitor. They all sample the handshake at the falling edge before each rising edge, when the inputs set after the previous rising edge have settled, so they see exactly the values the design sees at the edge.

source
VeriJul.Components.send! — Function
send!(sim, bus, items; idle=0.0, rng=Random.default_rng(), max_cycles=nothing)

Drives items into the design through bus, one word per handshake, and returns once the last one is accepted. Holds each word with valid high until the design is ready, and leaves valid low afterwards.

idle (from 0 up to, but not including, 1) is the probability of inserting an idle cycle (valid low) before each word, to test that the design copes with gaps. max_cycles limits how long one word may wait for ready; then a WaitTimeout is thrown.

Call it from a @testbench task (or the main task) while the clock runs.

source
VeriJul.Components.receive! — Function
receive!(sim, bus, n; ready=1.0, rng=Random.default_rng(), max_cycles=nothing) -> Vector

Receives n words from the design through bus and returns them. Drives the bus's ready input: with ready < 1 (it must be above 0), ready is high in each cycle only with that probability, to test that the design handles backpressure. ready is left low afterwards.

max_cycles limits how long to wait for each word; then a WaitTimeout is thrown.

source
VeriJul.Components.StreamMonitor — Type
StreamMonitor(sim, bus; on_item=nothing) -> StreamMonitor

Watches bus without driving it, and records every word that moves: in mon.items, with the simulation time of each transfer in mon.times. on_item(x), if given, is called for each word, for example to feed a Scoreboard.

The monitor runs as a testbench task from the moment it is created. End it with stop!; it also ends quietly when the clock stops.

source
VeriJul.Components.stop! — Function
stop!(mon::StreamMonitor) -> Vector

Stops the monitor after the current cycle and returns the words it saw.

source
VeriJul.Components.Scoreboard — Type
Scoreboard(name=""; sim=nothing, compare=isequal)

Checks that a design produces the expected values, in order. Queue what should come out with expect!, report what did come out with observe!, and check the result with @test passed(sb). Showing the scoreboard lists every mismatch, with the simulation time when sim is given.

sb = Scoreboard("fifo"; sim)
expect!(sb, data...)
mon = StreamMonitor(sim, out; on_item = x -> observe!(sb, x))
...
@test passed(sb)

compare(expected, got) decides whether two values match.

source
VeriJul.Components.expect! — Function
expect!(sb, values...) -> sb

Queues values the design should produce next, in order.

source
VeriJul.Components.observe! — Function
observe!(sb, value) -> Bool

Compares a value the design produced with the oldest expected one, records a mismatch if they differ (or if nothing was expected), and returns whether it matched.

source
VeriJul.Components.passed — Function
passed(sb) -> Bool

true when every observed value matched and nothing expected is still outstanding.

Internal signal access

VeriJul.Device.signal — Function
signal(dut, name) -> Signal

Looks up a signal anywhere in the design by its hierarchical name, relative to the top module: "count", "u_core.state", "inv.y". The design must be loaded with load_dut(...; internals=true). signals lists the names.

dut = load_dut("fifo.v", "fifo"; internals=true)
occupancy = signal(dut, "count")
occupancy[]          # read
occupancy[] = 0      # write

dut["count"] and dut["count"] = 0 are shorthand for one-off access; keep the Signal when reading the same signal often, since the lookup is the slow part. Parameters can be read but not written; arrays and memories (reg [7:0] mem [0:3]) are listed by signals but can't be accessed yet.

A write deposits a value: it holds until the design's own logic next assigns the signal (for a register, typically the next clock edge). Call settle! to update logic that depends on it before the next edge.

source
VeriJul.Device.signals — Function
signals(dut) -> Vector{String}

The hierarchical names of all signals in the design (ports included), relative to the top module, for use with signal. Needs a design loaded with internals=true.

source
VeriJul.Device.Signal — Type
Signal

A handle to a signal anywhere in the design hierarchy, from signal. Read it with sig[] and write it with sig[] = value. Values have the same types as ports: UInt8 to UInt64 up to 64 bits, BigInt above.

Waveform recording

VeriJul.Waves.WaveRecorder — Type
WaveRecorder(sim; cycles=1000, signals=nothing, dir=nothing, max_files=5)

Keeps the last cycles clock cycles of signal values in memory, so that when something goes wrong you get a small waveform of just the moments before it, even in a run of millions of cycles.

  • signals: what to record. By default all ports. Give a list of port names (:count) and, for designs loaded with internals=true, internal signal names ("u_core.state").
  • dir: when set, the recorder saves a VCD file there by itself whenever a @testbench task fails or a @test inside one fails, and logs the file's path. At most max_files files are written.

Save the window at any time with save_waves, and stop recording with stop_recording!.

rec = WaveRecorder(sim; cycles=200, dir="failures")
# ... run the test; a failure writes failures/failure_1.vcd ...

The recorder samples after every evaluation (every clock edge), so it costs a little time per edge; enable_trace! records everything instead, for the whole run.

source
VeriJul.Waves.save_waves — Function
save_waves(rec, path) -> path

Writes the recorded window to a VCD file that any waveform viewer (GTKWave, Surfer, …) opens.

source
VeriJul.Waves.stop_recording! — Function
stop_recording!(rec)

Stops the recorder. What it recorded can still be saved.

Coverage and random stimulus

VeriJul.Coverage.CoverGroup — Type
CoverGroup(name, :point => bins, ...; cross=[])

Functional coverage: which interesting cases a test has actually exercised. Each cover point names a value you sample! and lists its bins. A bin is

  • "label" => matcher, where the matcher is a range or collection (0:15, [1, 2, 4]), a predicate (iseven, x -> x > 100) or a value;
  • or just a value, which is its own bin (0, :read).

bins splits a range into equal bins. cross lists tuples of point names whose combinations of bins should be covered.

cg = CoverGroup("gcd inputs",
    :a => ["zero" => 0, "small" => 1:15, "large" => 16:65535],
    :b => ["zero" => 0, "small" => 1:15, "large" => 16:65535],
    :equal => [true, false];
    cross = [(:a, :b)])

sample!(cg; a = 12, b = 300, equal = false)
coverage(cg)      # fraction of bins hit, 0.0 to 1.0
uncovered(cg)     # what is still missing

A sample counts towards every bin it matches. Showing the group prints a report with the hits per bin.

source

sample!(cg; point=value, ...) -> cg
sample!(cg, (point=value, ...)) -> cg

Records one sample: each named point's value is matched against its bins. Every point of the group must be given.

VeriJul.Coverage.bins — Function
bins(range, n) -> Vector{Pair{String,UnitRange}}

Splits range into n bins of (nearly) equal size, labelled by their bounds: bins(0:255, 4) gives "0:63" => 0:63, …, "192:255" => 192:255.

VeriJul.Coverage.test_seed — Function
test_seed(; env="VERIJUL_SEED") -> UInt64

A seed for a test's random number generator, logged so a failing run can be reproduced. Takes the seed from the environment variable env if it is set, and picks a fresh random one otherwise.

using Random
rng = Xoshiro(test_seed())
# [ Info: Random seed 0x5f3a…; rerun with VERIJUL_SEED=0x5f3a… to reproduce

Pass the rng to everything random in the test (rand(rng, …), send!, …) so the whole run repeats.

Building

VeriJul.Builder.build_dut — Function
build_dut(sources, top_module; kwargs...) -> lib_path

Verilates sources (one path or a vector of paths) with top_module as the top, generates the C++ shim and compiles everything into a shared library. Returns the library's path; load it with DUT(lib_path, top_module).

Most code should call load_dut, which builds and loads in one step and takes the same keywords.

Keywords

  • build_dir: where build files go. By default each design and set of options gets its own folder in VeriJul's build cache (a Scratch.jl space, removed with clear_build_cache or when VeriJul is uninstalled). A directory you pass must be empty, new, or one VeriJul created earlier; VeriJul never deletes files it didn't create.
  • include_dirs=String[]: directories searched by $`include$ (-I).
  • defines=Dict(): preprocessor macros, e.g. Dict("DEPTH" => 16, "FAST" => nothing) (+define+).
  • parameters=Dict(): top-level parameter overrides, e.g. Dict("WIDTH" => 12) (-G). Values are passed to Verilator as written, so string parameters need their own quotes: "\"name\"".
  • verilator_args=String[]: extra command-line arguments for Verilator.
  • internals=false: also make internal signals (not just ports) readable and writable, with signal and dut["path"]. This passes --vpi --public-flat-rw to Verilator, which makes the model slower and the build bigger, so it is off by default.
  • trace=:vcd: the waveform format enable_trace! writes, :vcd or :fst. FST files are much smaller, but need the zlib development headers, and with Verilator 5.032 or newer also lz4's (apt install zlib1g-dev liblz4-dev, brew install lz4).
  • force=false: rebuild even if nothing changed.
  • verbose=false: show Verilator and compiler output.

Builds are cached: if the sources, files in include_dirs, options, Verilator version and compiler are unchanged, the existing library is reused. To rebuild, VeriJul empties the build directory first. Files pulled in by $`include$ from outside include_dirs are not tracked; pass force=true after changing them.

Set the CXX environment variable to choose the C++ compiler (default g++, or c++ on macOS; CXX="ccache g++" also works). Set VERIJUL_VERILATOR to choose the Verilator executable (see verilator_cmd).

VeriJul.Builder.generate_bindings — Function
generate_bindings(ports, module_name; internals=false, trace=:vcd) -> String

Generates the C++ shim that exposes the model through a C ABI: model creation, evaluation, waveform tracing, a get_<port> function for every port and a set_<port> function for every input. DUT calls these.
